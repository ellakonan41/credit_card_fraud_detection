Détection de fraude bancaire

La problématique

Sur l'ensemble des paiements par carte, moins de 0,2 % sont frauduleux — mais ils pèsent lourd dans les pertes. L'enjeu : repérer ces transactions en temps réel (quelques millisecondes), en détecter le maximum, sans noyer les équipes de vérification sous les fausses alertes.

Comment tester le modèle ici

En production, une transaction arrive depuis le système de paiement sous la forme d'une trentaine de valeurs numériques. 28 d'entre elles (V1 à V28) sont anonymisées par transformation PCA pour protéger les données des clients et des commerçants — elles n'ont donc aucune signification lisible, impossible pour un humain de les saisir à la main.

Cette démo pioche donc de vraies transactions dans le jeu de test (jamais vues par le modèle pendant l'entraînement). Comme on connaît leur vraie nature, on peut afficher si le modèle a vu juste.

Pourquoi le seuil de décision est à 13,5 % et non 50 % ?

Le modèle produit une probabilité de fraude entre 0 et 100 %. Il faut choisir à partir de quel niveau on déclenche une alerte. En détection de fraude, laisser passer une fraude coûte bien plus cher que vérifier une fausse alerte. On abaisse donc ce seuil à 13,5 % : le modèle signale au moindre doute sérieux, ce qui lui fait détecter environ 88 % des fraudes. Ce seuil a été choisi en optimisant le F2-score, une métrique qui donne plus de poids au rappel (fraudes détectées) qu'à la précision.
